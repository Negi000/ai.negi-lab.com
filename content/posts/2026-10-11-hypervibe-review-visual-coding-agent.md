## 結論から: このツールは「買い」か

結論から述べると、**「複数のAIエージェントを自律的に動かして、複雑なプロジェクトを完結させたい人」にとっては、現状で最もストレスの少ない選択肢の一つ**です。

逆に、ChatGPTやClaudeのチャット欄でコードをコピペして満足している層には、オーバースペックすぎて使いこなせないでしょう。評価としては星4.5。

私が特に評価したのは、エージェントが「今何を考え、どのファイルに手を出し、どこでエラーを出したか」を、フロー図のように俯瞰できる点です。これまでAiderやOpenDevinをCLI（コマンドライン）で動かしていた時に感じていた「ブラックボックス感」が解消されます。一方で、キャンバスを整理する手間が発生するため、スピード重視の微修正には向きません。

## このツールが解決する問題

従来のAIコーディングは、チャットUIか、あるいはターミナル上でエージェントが勝手にファイルを書き換える形式が主流でした。しかし、これには決定的な弱点があります。「エージェントが間違った方向に進み始めたとき、止めるタイミングが難しい」という点です。

例えば、大規模なリファクタリングを依頼した際、エージェントがAファイルの修正を起点にB、C、Dと関連ファイルを連鎖的に書き換えることがあります。この時、Bの時点でロジックが破綻していても、ターミナル上ではログが流れてしまい、最終的な出力を見るまで気づけません。

Hypervibeはこの問題を「空間的な管理」で解決します。無限に広がるボード上に、エージェントという「ノード」を配置し、それらが生成した中間成果物をカード状に展開します。

私たちがホワイトボードを使ってシステム構成を考えるように、AIの思考プロセスをキャンバスに広げることで、分岐した複数の解決策を並列で実行し、最も筋が良いものだけをメインブランチに統合する、といった高度な使い方が可能になります。

## 実際の使い方

### インストール

Hypervibeはデスクトップアプリケーション、またはローカルサーバーとして動作します。環境構築は非常にシンプルで、基本的にはNode.js環境があれば数分で起動まで漕ぎ着けます。

```bash
# 公式の推奨手順に基づいたセットアップ例
git clone https://github.com/hypervibe/hypervibe-oss # OSS版の場合
cd hypervibe
npm install
npm run dev
```

設定画面でOpenAIやAnthropicのAPIキーを入力すれば、すぐにキャンバス上でエージェントを召喚できます。

### 基本的な使用例

Hypervibeの真骨頂は、単一のプロンプトではなく「エージェントの定義」をボード上で行う点にあります。以下は、ドキュメントに基づいた「コードレビュアー」エージェントと「実装者」エージェントを連携させる際の設定イメージです。

```python
# 内部的に実行されるエージェント定義のシミュレーション
from hypervibe import Agent, Board

# ボードの初期化
board = Board(project_path="./my-web-app")

# 実装担当エージェント
coder = Agent(
    role="Senior Python Developer",
    model="claude-3-5-sonnet",
    instruction="FASTAPIの認証ロジックを実装してください"
)

# レビュー担当エージェント
reviewer = Agent(
    role="Security Specialist",
    model="gpt-4o",
    instruction="coderの出力をセキュリティの観点から厳格にレビューしてください"
)

# ボード上でエージェントを接続（視覚的な接続がこのコードに対応）
board.connect(coder, reviewer)
board.run()
```

このように、異なる特性を持つモデル（例えば、賢いが高いClaude 3.5 Sonnetと、安くて速いGPT-4o miniなど）を、それぞれの役割に応じてキャンバス上で繋ぎ合わせ、ワークフローを構築できるのが強みです。

### 応用: 実務で使うなら

実務では、「テスト駆動開発（TDD）ループ」を自動化する使い方が最も強力です。

1. **Test Agentノード**: 仕様書からpytestのコードを生成する。
2. **Impl Agentノード**: テストを通るように実装コードを書く。
3. **Runnerノード**: 実際にローカルでテストを実行し、エラーログをImpl Agentにフィードバックする。

この3つのノードをループ状に繋いでおけば、人間はキャンバスを眺めているだけで、勝手にテストがパスするまでコードが洗練されていきます。これは従来のIDE一体型AIでは画面が狭すぎて実現しにくかった「AI同士の対話の可視化」です。

## 強みと弱み

**強み:**
- **思考の並列化:** A案とB案の修正を別々のノードで同時に走らせ、結果を比較してから採用できる。
- **コンテキスト管理:** ボード上の特定の範囲だけをAIに見せるなど、トークン節約と精度向上が容易。
- **ヒューマンインザループ:** エージェントが生成した中間コードを、人間がその場で書き換えてから次のエージェントに渡せる。

**弱み:**
- **画面の解像度不足:** ノードが増えると、ノートPCの画面では狭すぎて管理が困難になる。4Kモニター以上が事実上必須。
- **APIコストの爆発:** 並列でエージェントを動かすと、1回のタスクで数ドル（数百円）単位のAPI使用料が飛ぶことがある。
- **日本語情報の欠如:** 公式ドキュメントもコミュニティも英語がメイン。設定の細かなニュアンスを理解するには英語耐性が必要。

## 料金・必要スペック・導入前の注意点

Hypervibe 2自体は一部機能がサブスクリプション制、またはOSS版でのセルフホストが可能です。しかし、ツール自体の価格よりも「API費用」と「マシンパワー」に注意が必要です。

複数のエージェントを常時稼働させるため、バックグラウンドでのトークン消費が激しいです。また、ブラウザベースであっても、大量のノードを展開するとメモリを数GB単位で消費します。

さらに、エージェントにローカルファイルを直接操作させる場合は、プロジェクトのバックアップ（Gitのコミット）は必須です。エージェントが予期せぬ範囲を破壊するリスクは、この手のツールには常に付きまといます。

快適に使うなら、メモリは最低でも32GB、ディスプレイは27インチ4Kのデュアル構成が望ましいです。特にDellのU2723QEのような、ハブ機能が充実した高精細モニターは、無限キャンバスを扱うエンジニアにとって投資価値の高いデバイスになります。

個人的な評価は **★4.5** です。

これまでのAIツールが「優秀な秘書」だったのに対し、Hypervibeは「開発チーム全体をマネジメントする司令室」のような感覚を与えてくれます。特に、エージェントがループに陥った際、視覚的に「あ、ここで詰まってるな」と一瞬で判断して接続を切り離せるのは、実務において大きな時間短縮になります。

Hypervibeを導入すべきなのは、「新規プロジェクトのボイラープレート作成から、DBスキーマ設計、認証実装までを、一気にAIにやらせたい」という、AIを「相棒」ではなく「労働力」として扱いたい中級以上のエンジニアです。

## よくある質問

### Q1: ローカルLLM（Ollama等）でも動かせますか？

基本的にはAPIベースですが、OpenAI互換のAPIエンドポイントを叩けるため、OllamaやLocalAIを介してローカル実行可能です。ただし、エージェントとしての自律的な判断能力を求めるなら、Llama 3の70Bクラス以上のモデルをRTX 4090等のVRAM 24GB級GPUで動かす必要があります。

### Q2: 既存のVS Codeプロジェクトと同期できますか？

はい。Hypervibeで開いたディレクトリへの変更はリアルタイムでファイルシステムに反映されます。したがって、キャンバスでAIに大まかな構成を書かせ、細かなコードの整形やシンタックスハイライトの確認は、隣に開いたVS Codeで行うという使い方が一般的です。

### Q3: セキュリティ面でのリスクはありますか？

エージェントにファイルの「書き込み権限」を与えるため、信頼できないカスタムノードやプロンプトを外部から取り込む際は注意が必要です。特に、シェルコマンドを実行する権限を持つノード（Runner）を配置する場合、意図しない `rm -rf` 等が発生しないよう、Dockerコンテナ内などのサンドボックス環境で動かすのがセオリーです。
